    Test suite audit (consolidated)¶

    Snapshot as of commit cfdae0d, audit date 2026-11-18. This is an audit report, not a feature doc; nothing here has been applied. All verdicts are recommendations. The raw per-test evidence is in the 13 shard reports in this directory (S1..S9 = .fire tests, P1..P4 = Python tests); section references below point at them.

    1. Summary¶

    What was audited¶

    Kind Shard(s) Count
    Run tests (tests/sources/<cat>/*.fire, standalone) S1 49, S2 60, S3 53, S4 51, S5 58, S6 42 313
    Compile-fail tests (tests/sources/invalid/**, incl. 11 known_issues) S7 72, S8 61, S9 50 183
    Python test functions (tests/python/**) P1 218, P2 about 415, P3 343, P4 274 about 1250 (P4's test_encode also expands to 96 param cases)

    Helper .fire files were not judged as tests. Snapshot (.fir/.flir) contents and the determinism kind were not reviewed in depth (S2: existence only). The harness itself was not run for this document.

    How¶

    • Run tests: every file compiled and run under wine in private temp dirs; outputs compared to the EXPECT block, and the expected values independently re-derived (Python oracles, hand arithmetic, Python re for regex, quadmath for float128). All 313 run tests match their EXPECT blocks; no EXPECT block was found numerically wrong. S3 and S5 found no EXPECT that blesses an arithmetic bug, but several pin behavior that contradicts the docs (section 4).
    • Compile-fail tests: every file run through --check --message-format json; annotations compared to real diagnostics; un-annotated lines probed in isolation (check and full compile) to separate primary errors from cascades and wrong-reason passes; about 30 scratch programs per shard probed for missed diagnostics.
    • Python tests: judged by mutation in private rsync copies (never the shared repo), per-test coverage vs the union of all .fire tests (P1), rule-branch relabel mutation (P2), 343-test mutation runs (P3), differential checks vs host as and libquadmath (P4).

    Headline conclusions¶

    1. The run-test suite is correct but padded: about 64 of 313 files are redundant or trivial (deletable), about 25 more can be merged away, and about 55 are WEAK (assertion cannot detect the bug the header claims).
    2. The compile-fail suite is the weakest area: about 59 of 183 files are duplicates, and about 24 are INCORRECT (they pass for the wrong reason: un-imported print, cascades, comment-token artifacts, obsolete syntax). One is failing right now (invalid/operators/operator_errors.fire, see 5.2).
    3. About 1/3 of the Python tests are removable (duplicates across files, tests of dead code, tautologies). Roughly 145 of the ~400 deletions are coverage-only tests of unreachable guards that contradict the CLAUDE.md philosophy.
    4. The audit found 54 distinct compiler bugs / missing diagnostics (section 3), of which 15 are internal compiler errors or crashes and 7 are silent wrong results. Only the 11 invalid/known_issues files exist; there is no run-kind known-issues directory (tests/sources/known_issues/ does not exist per S4/P2), so none of the ICEs or wrong-result bugs is tracked by a test.
    5. At least 8 existing tests pin a compiler bug as expected behavior (section 2, theme 7). Fixing the bug will break them; they must move, not be "fixed to pass".
    6. 24 docs-vs-compiler conflicts need an owner decision (section 4).
    7. Blind spots no test can see today: heap leaks/double-free (runtime ignores them), float precision (everything printed with %f), float128 end-to-end correctness (only the Python oracle is tested), NaN/inf, out-of-range indexing, integer overflow semantics.

    2. Cross-cutting themes¶

    1. EXPECT blocks are auto-blessed from compiler output. Corollary: they are only as right as the compiler. Everything checked here was right for arithmetic, but 4 tests bless behavior the docs forbid (wrap on overflow: types/types_int8, types/types_uint8, edge_cases/edge_cases_overflow_underflow, performance/stress_integer_overflow), and arrays/array_tests blesses the [...] placeholder for println(array). --update (bless) needs a "does this agree with the docs?" review step.
    2. Compile-fail tests passing for the wrong reason.
    3. Un-imported print/println yields FS-PARSE-0012 "Function 'print' is not defined" and also masks the missing-semicolon error on the same statement. About 30 annotations in invalid/types/type_mismatches, invalid/arrays/array_edge_invalid, invalid/control_flow/control_flow_invalid, invalid/types/cast_and_generic_type_errors (line 39), invalid/syntax/syntax_errors (9 of 22), invalid/syntax/syntax_comprehensive, invalid/functions/function_errors, invalid/classes/class_errors are this incidental error (S8, S9, S7).
    4. Parse errors stop the pipeline before semantic analysis, so any file mixing a parse error with semantic mistakes silently hides the semantic ones (class_errors, generics_errors).
    5. Cascade annotations pin error-recovery noise ("Variable 'this' not defined" after a bad parameter list, "Function 'Pair' is not defined" after a bad generic header, 3-4 diagnostics per enum payload typo). About 20 files; any recovery improvement breaks them (S7 D6, S8 cross-cutting, S9 12).
    6. "Comprehensive" files carry commented or un-annotated error lines that demand nothing (array_errors, type_errors_comprehensive, statement_form_errors l.30, literal_errors, operator_errors l.19-20 / 53-54, scope_errors l.13).
    7. Comments are ordinary parser tokens, so the harness //~ comment can change compiler behavior: expression_at_eof pins a diagnostic whose text is literally the annotation comment; enum_def_errors / enum_body_syntax_errors pin 4 spurious "Expected ',' or '}'" diagnostics caused by the annotation comment after the last variant (bug B28).
    8. Obsolete name-first syntax (T x;, Pair<..> p, int beforeDecl) in several old tests makes them test statement dispatch instead of the stated rule (S7 D3, generics_errors, class_errors).
    9. Contrived tests that exist only to hit unreachable lines, contradicting CLAUDE.md ("defensive or unreachable lines don't need contrived tests"). About 100 of P1's 218 tests (*_dead_guards*, *_internals, *_coverage), 26 in P3 (test_heap_verifier_defensive, test_lowering_defensive_errors, SyscallResult bootstrap), plus P2 (test_ownership_map, _StateDict, test_ir_types), P4 (call_numeric_target, encode_emits_no_bytes). They freeze dead code: the production helpers expect(), _recover_to_statement_boundary, _resolve_struct_type, most ParserBase error helpers, OwnershipMap.declare/..., _StateDict have no callers.
    10. Harness strips trailing blank lines (tests/harness/expectations.py:20, normalize_output). A final println("") is never asserted: strings/strings_index_of_substring (last case substring(10,2)), strings/strings_upper_lower, edge_cases/edge_cases_zero_values, several regex error tests ("valid pattern" cases print empty last lines; partly protected because a regression would add a non-empty line).
    11. Float printing via %f hides precision. Every float assertion has 6 decimals; float32 vs float64 storage, float128 binary128 vs binary64, rounding, subnormals are invisible (types_float32, types_float64, float128_ops, conversions_float_precision). inf/nan print as inf/nan and are untested. float128 has no end-to-end validation: tests/python/float128 tests the Python oracle against itself (P4), and the docs' "bit-exact fuzz vs oracle" is not committed.
    12. No runtime leak / double-free detection, so drop tests are blind. Runtime free is registry-based (std/internal/alloc.fire fs_rt_free): double free and free of string literals are silently ignored; string literals are untracked; fixed-array .length() is constant-folded (S1). Tests such as memory_branching, memory_scopes, memory_early_return, memory_break_continue_owned, memory_reassign, copyable_local_drop claim drop correctness but assert nothing observable; only FIR/FLIR snapshots or heap-payload tests can. Leaks are caught only statically by the heap verifier.
