    Compiler bugs discovered¶

    • B1 (lowering.py _decimal_to_f128_bits, subnormal branch, ~line 126): a float128 literal in the subnormal range whose rounded significand reaches 2^112 is clamped to the largest subnormal (0x...ffff) instead of rounding up to the smallest normal (hi=0x0001000000000000, lo=0). 1 ulp error. Repro (no .fire needed): from flir.lowering import _decimal_to_f128_bits as d; d("3.36210314311209350626267781732175234359107456732546680313127e-4932") -> (0xffffffffffffffff, 0xffffffffffff); oracle: (0, 0x1000000000000). Extremely obscure literal; fix is if sig >= 1<<112: return (0, sign<<63 | 1<<48) which makes only the pinning test fail.
    • B2 (flir/lowering.py:1023 lower_binary): float128 ** float128 crashes the compiler with an uncaught Python traceback flir.lowering.LoweringError: unsupported float128 operator ** instead of a user diagnostic. No tests/sources known_issues entry exists for it (only this unit test's comment mentions it).
