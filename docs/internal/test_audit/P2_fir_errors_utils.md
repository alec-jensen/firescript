# P2 audit: tests/python/{fir,errors,utils,log_formatter}

Method: read every test and the code under test (fir/verifier.py, fir/ownership_verifier.py, errors.py, log_formatter.py, utils/*). Ran two mutation campaigns in private copies (never the shared repo; no git changes):
(a) every `emit("FIRV-x")`/`Violation("FIRV-x")` line relabelled to FIRV-ZZ, then tests/python/fir+errors run: which tests die per rule branch (the "killers");
(b) ~80 logic mutants (conditions inverted/dropped). Raw results: scratchpad/audit/mut.json and scratchpad/audit/p2mut/res*.json, logs p2mut/log_*.txt.
Caveat found while mutating: the harness leaves stale `__pycache__`; same-size source mutations within the same second silently reuse old bytecode, so every mutant run deleted `__pycache__` first.

## HEADLINE FINDING: massive duplication across the four Tier-1 verifier files
Rule-branch mutation shows almost every Tier-1 branch is killed by exactly 2 tests with identical bodies in different files (e.g. FIRV-T7 StoreField non-class: `test_verifier_more::test_t7_store_field_non_class_operand` and `test_verifier_types::test_t7_store_field_object_non_class_type`). Cross-file clusters (same rule branch, near-identical input):
- S6 dup type/function/constant, enum no variants, enum has base, unresolved base, cyclic base, generic ref omits args, generic instance wrong arg count: in test_verifier_structure.py (9), test_verifier_more.py (9+3), test_verifier_structural_and_method_call.py (10). Three copies each.
- D1/D2/D3 operand resolution: structure(4-5), more(4), structural_and_method_call(2), types_extra(3 "lenient").
- T1/T2 binop/unary: types(7) vs more(6) vs types_extra(4) (e.g. test_t1_arithmetic_result_type_mismatch, test_t1_string_concat_result_not_string, test_t1_logical_operand_not_bool exist with identical names/bodies in types and more).
- T5/T6 call/method-call arg-count/arg-mode/result-type/shape: types, more, types_extra, structural_and_method_call, checks.
- T7-T12, G1, G3: types vs more (identical names, e.g. test_t10_*, test_t11_*, test_g3_gen_new_*, test_g3_gen_value_*).
Net: ~85 of ~230 verifier tests could be deleted with zero loss of rule-branch coverage; keep one per branch (preferably in one file, `@t.params`).
